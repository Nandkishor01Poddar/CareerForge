# AI Career OS — Security Requirements

## 1. Security Goals

Protect:
- authentication credentials
- student profile data
- resumes
- application information
- AI inputs/outputs
- private project data

## 2. Authentication

### Passwords
- Hash using Argon2id or bcrypt.
- Never store plaintext passwords.
- Never log passwords.
- Enforce sensible password requirements.

### Access Tokens
- Short lifetime.
- Minimal claims.
- Do not place sensitive profile information inside tokens.

### Refresh Tokens
- Prefer secure HttpOnly cookies.
- Use Secure in production.
- Use SameSite policy appropriate to deployment.
- Hash stored refresh-token representations.
- Rotate tokens when appropriate.
- Revoke on logout/password reset.

## 3. Authorization

Use server-side ownership checks.

Example rule:

```text
resource.userId === authenticatedUser.id
```

Admin role must be checked separately.

Do not rely on:
- hidden frontend buttons
- route obscurity
- client-supplied user IDs

## 4. Input Validation

Validate:
- body
- params
- query
- uploaded files
- URLs
- enum values
- numeric bounds
- string lengths

Use a centralized schema validation layer.

## 5. Injection Protection

Protect against:
- NoSQL injection
- command injection
- XSS
- SSRF
- prototype pollution
- malicious file uploads

Avoid constructing MongoDB queries directly from arbitrary client objects.

## 6. Rate Limiting

Rate-limit:
- login
- register
- password reset
- email verification
- AI endpoints
- practice submission endpoints

Use Redis-backed rate limiting when horizontally scaled.

## 7. CORS

Production:
- explicit frontend origin allowlist
- no wildcard when credentials are used

## 8. Security Headers

Use a maintained security-header middleware such as Helmet for:
- CSP where practical
- frame protections
- MIME sniffing protections
- referrer policy
- related browser security headers

## 9. CSRF

If authentication uses cookies, implement an appropriate CSRF defense for state-changing requests.

A double-submit cookie or synchronizer-token approach can be used depending on architecture.

## 10. AI Security

Treat all user/job-description content as untrusted input.

Controls:
- prompt injection defenses
- strict output schemas
- max input length
- provider timeouts
- output length limits
- no direct execution of model-generated code
- no direct database commands generated by AI
- no autonomous external actions in V1

## 11. AI Hallucination Controls

AI must not invent:
- degrees
- grades
- work experience
- projects
- certifications
- achievements
- job requirements

Generated resume suggestions must be derived from stored user facts.

## 12. File Upload Security

If resume/image uploads are supported:
- allowlist MIME types
- validate actual file type
- size limits
- malware scanning where appropriate
- random storage keys
- private object storage
- signed URLs for access

## 13. Secrets

Never commit:
- JWT secrets
- database passwords
- SMTP passwords
- AI API keys
- cloud credentials

Use environment variables or a secrets manager.

## 14. Logging

Log:
- request ID
- endpoint
- status
- latency
- relevant actor ID
- security events

Do not log:
- passwords
- tokens
- OTPs
- authorization headers
- unnecessary resume contents

## 15. Database Security

- least-privilege database account
- TLS
- network restrictions
- backups
- monitoring
- no public database exposure where avoidable

## 16. Account Deletion

Deletion must consider:
- user
- profile
- skills
- projects
- resumes
- applications
- practice history
- AI jobs
- notifications

Define whether records are deleted, anonymized or retained for legal/operational reasons.

## 17. Security Testing

Before production:
- dependency audit
- authentication tests
- authorization tests
- rate-limit tests
- input validation tests
- NoSQL injection tests
- XSS tests
- CSRF tests where applicable
- IDOR/ownership tests
- secret scanning
- basic penetration testing

## 18. Threat Model Priorities

High-priority threats:
1. account takeover
2. IDOR / cross-user data access
3. credential leakage
4. malicious file upload
5. prompt injection
6. abuse of AI endpoints
7. database injection
8. leaked secrets
